***ASSIGNMENT 3 --> Access Control Logging***


*OVERVIEW* :

    This project implements an Access Control Logging Audit system that monitors and logs file access and modifications across the system using the **LD_PRELOAD monnitor mechanism** to override specific I/O functions from the standard C library. The audit tracks every file open (fopen), write (fwrite) and close (fclose) operation and records a detailed information in a structured log.


# Step 1: Audit Logging Library

*OVERVIEW* :

    In step 1, we implement the **audit_logger** component, which formats each log record with a timestamp, user information, the file path involved, the operation type, and the result of the action. The logger outputs these entries to a system-wide log file named access_audit.log

*LOG ENTRY FORMAT* :

    UID         -->     The unique user ID (use geteuid()).
    PID	        -->     The process ID performing the action (use getpid()).
    Filename    -->     Absolute path of the accessed file.
    Date        -->     The date when the event occurred (UTC).
    Time        -->	    The exact time (UTC).
    Operation	-->     Type of file operation:  0 = created
                                                 1 = opened
                                                 2 = written 
                                                 3 = closed
    Denied flag	-->     1 if the operation was denied (no access privileges), 0 otherwise.
    File hash   -->     SHA-256 hash of the file contents (use OpenSSL EVP).

# Step 2: Audit Log Analyzer 

*OVERVIEW* :

    In step 2, we implement the **audit_monitor** component, which analyzes the log generated by audit_logger.so. Specifically, it detects malicious users via the list_unauthorized_accesses fuction, as well as analyze the file activity (users who accessed it, modifications occured) via the list_file_modifications function.

*TOOL SPECIFICATIONS* :

        -s             -->     Prints malicious users
        -i <filename>  -->     Prints table of users that modified the file <filename> and the number of modifications
        -h             -->     Help message

# Step 3: Testing the Audit System 

*OVERVIEW* :

    In step 3, we implement the **test_audit** component, which demonstates and validates the functionality developed in steps 1 and 2. This test program creates multiple files and performs a series of controlled operations on them, such as creation, opening, writing, and closing (op=0,1,2,3). Furthermore, it also performs actions that should fail, to check that the audit monitor correctly logs denied accesses and detects malicious or unauthorized behavior. 

*FILES* :

    1. audit_logger.c
    2. audit_monitor.c
    3. test_audit.c
    4. audit_logger.so 
    5. Makefile

*COMPILATION - BUILD* :

    Compile the audit_logger:       gcc -Wall -fPIC -shared -o audit_logger.so audit_logger.c -lcrypto -ldl
    Complie the audit_monitor:      gcc audit_monitor.c -o audit_monitor
    Compile the test_audit:         gcc test_audit.c -o test_audit

    In order to run the project:    LD_PRELOAD=./audit_logger.so ./test_audit

    Or you may use the default Makefile given.

*EXECUTION* :

    ./audit_monitor -s                  Parses the log file and prints all the malicious users (UID) who attempted to access more than 5     
                                        distinct files where the action was denied
    ./audit_monitor -i <filename>       Prints all users who accesed the file, how many times they modified it and how many modifications occured
    ./audit_monitor -h                  Help message
    cat /tmp/access_audit.log           Shows all the logs in the files
